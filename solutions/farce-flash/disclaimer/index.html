F.A.R.C.E. Flash is a joke. Farce Systems is a satirical project by Joshua Hickson. Everything on the campaign page is written in the voice of a hardware startup that sincerely believes it can replace 128 GB of unified memory with forty consumer MicroSD cards. It cannot. That is the point.

It is the "download more RAM" joke, built. For twenty years a certain kind of website has offered to sell you more memory as a download. This is that, made physical: a peripheral you attach to a computer you already own, which causes the operating system to report a larger number without making anything faster. The only differences are that the parts are real, they arrive in a box, and the number the kernel prints is true.

The Feasibility Report is real, and it says so. It was generated with AI research tooling and published without edits to its content, tone, or conclusion. It concludes that the architecture achieves "less than 5% of the performance of the hardware it sought to disrupt" and that the array destroys its own storage media in roughly 64 days. We fixed typographic artifacts from the source export and nothing else. It is not a peer-reviewed document and its citations have not been independently verified. Read it as what it is: an argument against the product it analyzes.

Farce Systems is not a company. It is not registered, incorporated, or capitalized. It has no employees. The "two engineers" on the campaign page are fictional. One real person sources parts, packs boxes, and answers email.

What you would actually receive. A box of off-the-shelf electronic components, exactly as itemized on the kit page, and a single-sheet bill of materials. Every part is a commodity item with a public datasheet. There is no printed circuit board, no enclosure, no assembled hardware, and no software in any kit. Nothing you receive will run a language model. The kits containing a microcontroller dev board do contain a small computer, in the sense that an RP2040 board is one; it is not a machine capable of inference and nothing in any kit is. Assembly, if you attempt it, is entirely your own project.

What "system-addressable memory" means here. It means Linux swap. The forty cards are joined into a RAID 0 span and handed to the kernel as swap space, over USB in the validation rig and over SDIO in the reference design. The kernel will report the total in free, and that is the entire basis for the phrase. It is not RAM, it does not accelerate anything, and it is thousands of times slower than the memory in the machine you are reading this on — an aggregate of a few gigabytes per second at best, against the DGX Spark's 500-plus. That "at best" figure is a sequential one, and it is not the workload. Swap traffic is small and random, which is the pattern MicroSD is worst at — random 4 KB performance on these cards is orders of magnitude below their sequential rating, and forty readers sharing four USB uplinks caps it again. Do not treat the sequential number as a description of how this performs. Swapping a working set onto it makes a computer slower, not faster. The "10× the DGX Spark" claim on the campaign page compares capacity and only capacity.

No kit contains a computer, and you need one. Every kit is a peripheral: card readers, a board, and parts. To do anything at all the array must be attached to a Linux machine you already own or buy separately, with roughly 32 GB of RAM, because the architecture keeps the model's weights in that machine's memory. The ~4.1 GB/s figure quoted anywhere on this site is forty cards multiplied by their rated speed. It assumes a host that can absorb forty lanes at once, which needs about nine independent USB 3.0 controllers; a normal desktop has one, and adding hubs does not add controllers. On a machine you are likely to own, the array will deliver a fraction of that number. The NVIDIA DGX Spark is a complete computer and this is not, so any price comparison between them omits the cost of the computer.

A cheap SSD beats it. A $25 USB SSD outperforms this array on sequential write, random IOPS, latency, endurance, reliability, power draw and cost, and ties it on sequential read only because both are limited by the same USB controller. There is no arrangement of consumer MicroSD cards that beats one cheap SSD at anything. If what you want is fast storage, buy the SSD.

1.28 TB is raw capacity. It is forty times thirty-two gigabytes, before RAID 0 metadata, filesystem overhead, and reserved space. Usable capacity is approximately 1.2 TB. Manufacturers count a gigabyte as 1,000,000,000 bytes, so your operating system will report less again.

No performance is promised. Any speed, capacity, or capability figure anywhere on this site describes what the architecture targets, not what any kit does. Every one of those figures is published alongside the analysis that contradicts it.

OpenFARCE is written but unproven. The code is public and readable at https://github.com/joshhickson/openfarce. It is called pre-alpha because it has never run against the hardware it is written for — no array has been built and no measurement has been taken with it. It is not included in, or required by, anything sold here.
